# التشغيل والنشر

## معاينة الواجهة
1. افتح مجلد `blogger-studio` في المستودع.
2. الواجهة الثابتة موجودة في `index.html` و`assets/css/app.css` و`assets/js/app.js`.
3. لتشغيل GitHub Pages من مجلد فرعي، يمكن تفعيل Pages من إعدادات المستودع مع فرع `main` ثم اختيار الجذر عند نشر المشروع بالكامل، أو نقل محتويات المجلد إلى مستودع مستقل مخصص للواجهة.

## ربط Supabase (بعد إنشاء مشروع مخصص)
1. شغّل الترحيل `supabase/migrations/0001_initial_schema.sql` على مشروع Supabase جديد وفارغ.
2. احصل على Project URL وPublishable key من إعدادات المشروع.
3. أضف ملفات إعداد العميل إلى الواجهة بدون أي Service Role key.
4. اختبر المصادقة وسياسات RLS بحسابين مختلفين قبل إدخال أي محتوى حقيقي.
5. أضف سياسات Storage، وإدارة الصلاحيات الدقيقة، واختبارات SQL/RLS قبل الإنتاج.

## تنبيه مهم
الواجهة في هذا المجلد نموذج تفاعلي لا يحفظ البيانات في قاعدة البيانات. يجب ربط المصادقة والاستعلامات فعلياً قبل استخدام الحسابات أو المحتوى. كما أن GitHub Pages يستضيف ملفات ثابتة فقط ولا يشغّل خوادم أو مهام نشر مجدولة. لن يكون رابط GitHub Pages وحده منصة نشر مقالات عامة بمزايا نظام CMS كامل دون طبقة نشر إضافية.
